# Comprehensive Survey on Large Language Model Agents and Tool Use

## TL;DR
- Large Language Model (LLM) agents combine internal reasoning traces with external tool execution via interleaved paradigms like ReAct [1], self-supervised acquisition [2], and specialized API routing [3].
- Complex problem solving and software development are scaled through multi-agent collaboration frameworks (AutoGen [4], MetaGPT [5], ChatDev [6]) and structured search algorithms (Tree of Thoughts [7], Graph of Thoughts [8]).
- Evaluation environments such as AgentBench [9], WebArena [10], GAIA [11], and SWE-bench [12] reveal that while agents achieve high task success in controlled settings, they remain vulnerable to tool unreliability [13], prompt injections, and memory poisoning [14][15].
- Recent 2024–2026 advancements emphasize dynamic least-privilege scoping [16], enterprise data synthesis [17], and rigorous security benchmarks (CoSec [18], ASB [14]), highlighting the critical need for robust compositional defenses [15].

## Background
Large Language Model (LLM) agents represent a paradigm shift from static text generation engines to autonomous, goal-directed systems capable of perceiving environments, maintaining state, and executing external actions [19]. Traditionally, LLMs were bounded by static training corpora and parametric memory, leading to factual hallucinations and an inability to interact with real-time systems or specialized software tools. The foundational evolution toward agentic workflows began with modular neuro-symbolic designs such as MRKL Systems, which coupled LMs with discrete symbolic calculators and knowledge routers [20]. This laid the groundwork for interactive paradigms like ReAct, which prompts models to generate both verbal reasoning traces ("thoughts") and concrete environment interactions ("actions") in an interleaved loop, enabling models to track execution states, handle exceptions, and query external APIs like Wikipedia on demand [1]. 

Simultaneously, research addressed the challenge of teaching models how to invoke tools effectively. Toolformer demonstrated that LLMs can learn to autonomously decide which APIs to call, what parameters to supply, and how to integrate returned results through self-supervised fine-tuning on annotated pretraining data [2]. To overcome the fragility of general-purpose LMs when interacting with massive and evolving APIs, specialized models like Gorilla were developed via fine-tuning to write precise API calls and minimize argument hallucinations [3]. Furthermore, to optimize computational cost without sacrificing reasoning depth, frameworks like Large Language Models as Tool Makers (LATM) established closed-loop paradigms where powerful models create reusable Python utility functions for execution by lightweight models [21].

## Architectural Foundations and Reasoning Paradigms
Building upon foundational API-calling frameworks, agent architectures have expanded into sophisticated reasoning and execution loops. The ReAct framework established that interleaving thought and action significantly outperforms standard Chain-of-Thought reasoning by grounding model outputs in external environment feedback, achieving absolute success rate gains of 34% on ALFWorld and 10% on WebShop interactive decision-making tasks [1]. To enhance deliberate planning beyond linear reasoning, Tree of Thoughts (ToT) enables search over coherent units of text ("thoughts") combined with breadth-first or depth-first search algorithms, supporting lookahead, self-evaluation, and backtracking [7]. Generalizing this further, Graph of Thoughts (GoT) models reasoning as an arbitrary graph structure where intermediate thoughts are vertices and dependencies are edges, enabling advanced thought transformations such as merging independent subtask conclusions and feedback loops, which increases sorting task quality by 62% while reducing computational costs by over 31% [8].

For continual execution and specialized workflows, multi-agent collaboration frameworks have emerged as a dominant architecture. AutoGen introduced an open-source framework supporting flexible multi-agent conversations combining LLMs, human input, and tool execution [4]. MetaGPT advanced this by encoding Standardized Operating Procedures (SOPs) into prompt sequences to enforce structured workflows among specialized agent roles, mitigating cascading logic errors [5]. Similarly, ChatDev implements communicative agent teams across the software life cycle—incorporating design, coding, and testing modules guided by chat chains and a communicative dehallucination protocol where agents actively request missing context prior to code generation [6]. AgentVerse further generalizes multi-agent coordination through a four-stage problem-solving procedure encompassing expert recruitment, collaborative decision-making, action execution, and evaluation [22].

## Benchmarks and Empirical Evaluation Methodologies
As LLM agents proliferate across diverse domains, rigorous empirical evaluation has transitioned from static datasets to dynamic, interactive, and sandboxed environments [12][23]. Comprehensive surveys on agent evaluation reveal that traditional benchmarks rely heavily on binary success metrics while largely omitting critical deployment dimensions such as cost-efficiency, robustness, and security [12][23]. Standardized evaluation suites now span multiple interactive tiers: AgentBench assesses generalist agent capabilities across eight distinct interactive environments including operating systems, databases, and digital card games [9]; WebArena provides fully functional, self-hosted web applications to evaluate long-horizon professional workflows [10]; GAIA measures general AI assistant capabilities across multi-step tool use and messy file handling [11]; and SWE-bench establishes repository-level software engineering evaluation using real-world GitHub issues [12].

To address real-world operational challenges, recent evaluation paradigms focus on environment faults and security vulnerabilities. ToolBench-X benchmarks tool-using agents under tool-environment unreliability, testing performance against recoverable execution faults and environment anomalies [13]. Concurrently, security evaluation has gained paramount importance. AgentDojo evaluates prompt injection vulnerabilities across realistic email, banking, and travel scenarios [24], while Agent Security Bench (ASB) formalizes and benchmarks direct prompt injections, observation injections, memory poisoning, and Plan-of-Thought backdoor attacks across 13 LLM backbones, revealing attack success rates reaching up to 84.30% [14]. Comprehensive empirical assessments like SafeAgentBench further highlight that representative LLM agents achieve overall safety scores below 60%, underscoring severe risks in tool misuse and safety boundary recognition [25].

## Emerging Trends, Security Risks, and Open Challenges
The 2024–2026 research landscape highlights critical security vulnerabilities, architectural tensions, and scalable data synthesis methods in LLM agent deployments. A central security challenge stems from the fact that all context sources—including user prompts, retrieved documents, persistent vector database memories, shell outputs, and external tool results—enter a single shared planning channel with equal operational influence [16]. This architecture exposes agents to prompt injection, tool-mediated control-flow hijacking, and memory poisoning, where malicious instructions embedded in retrieved data redirect agent execution flows [15][26]. Furthermore, long-term memory implementations relying on vector databases expand the privacy attack surface through embedding inversion and structured extraction attacks [26].

To mitigate these risks, recent work emphasizes dynamic least-privilege scoping, where an agent's operational capabilities adjust dynamically based on task intent [16], and tool-filtering mechanisms that restrict write-access operations when processing untrusted read inputs [24]. In enterprise ecosystems, training and evaluating agents at scale is constrained by regulatory and schema privacy barriers; to overcome this, paradigms like Synthesis Through Simulation (STS) have emerged to generate coherent enterprise data via scalable agent-system interaction [17]. Additional open challenges include resolving logical relation violations in agent skills (as demonstrated by SLBench where 70% of public skills contain constraint or fallback conflicts [27]) and enforcing strict authorization boundaries across persistent collaborative community environments [18].
